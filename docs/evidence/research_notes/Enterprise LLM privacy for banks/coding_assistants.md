# AI coding assistants sold to banks and regulated enterprises: deployment, data policy, air-gap, customers, pricing (as of Sept 2026)

Research date: 2026-09-25. Facts are dated where they are older than mid-2026. "(search snippet)" means the claim came from a search-engine summary of the linked page, not a full fetch of the page. Treat those with a bit less confidence. The session's web-search budget ran out partway through, so some items could not be cross-checked (see Gaps).

## Q1. Vendor-by-vendor: retention/training, where inference runs, models, indemnity, exclusion/secret features, audit/SSO, certifications

### Takeaway
By 2026 almost every major vendor sells the same baseline to regulated buyers: no training on business data, zero or short retention, SSO/SCIM, audit logs, and SOC 2 / ISO 27001. They differ on where inference runs. The frontier-model tools (GitHub Copilot, Cursor, Claude Code, Codex, Devin/Windsurf, Augment, Amp, Gemini Code Assist, Kiro) all run inference in the vendor's or a hyperscaler's cloud. They respond to bank concerns with data residency, CMEK, customer-hosted *execution* (not inference), and customer-held logs. True on-prem or air-gapped inference is left to a smaller group (Tabnine, now owned by Tricentis; JetBrains AI Enterprise; GitLab Duo Self-Hosted; Sourcegraph Cody Enterprise with self-hosted models; Qodo; Refact; Tabby; Continue; Mistral Code).

### Cited Findings

**GitHub Copilot Business / Enterprise (Microsoft)**
- Training: "GitHub does not use either Copilot Business or Enterprise data to train its models." Org plans include IP indemnity, SAML SSO, usage metrics and codebase indexing, and Enterprise adds "fine-tuned custom, private models" — [GitHub Copilot plans](https://github.com/features/copilot/plans)
- Retention (search snippet; the Trust Center page itself returned no content): for Business/Enterprise, IDE prompts and suggestions for chat and completions are not retained. Prompts from GitHub.com, mobile and CLI are retained 28 days by default. User engagement data is kept 2 years. Copilot Business/Enterprise are in scope of GitHub's ISO 27001 certificate — [GitHub Copilot Trust Center FAQ](https://copilot.github.trust.page/faq); [Axonbuild summary](https://axonbuild.com/blog/github-copilot-security)
- Data residency and FedRAMP (announced 2026-04-13): US and EU Data Boundary (EU + EFTA, from 2026-05-01) data-resident inference, with Japan and Australia planned for later in 2026. FedRAMP Moderate models are available for US government. It covers all GA features (agent mode, inline, chat, cloud agent, code review, CLI). Launch models: GPT-5.4, Claude Sonnet 4.6 and Opus 4.6. **Gemini models are excluded because GCP lacks data-resident inference endpoints.** The policies are off by default, and data-resident requests cost a 10% premium-request multiplier (1 → 1.1) — [GitHub Changelog 2026-04-13](https://github.blog/changelog/2026-04-13-copilot-data-residency-in-us-eu-and-fedramp-compliance-now-available/)
- Content exclusion (Business/Enterprise only) removes files from inline suggestions, chat context and code review. Limits: not supported in VS Code **Edit and Agent modes**; Copilot "may use semantic information from an excluded file if the information is provided by the IDE indirectly" (types, hovers, build config); does not apply to symlinks or remote filesystems; Azure Data Studio unsupported — [GitHub Docs: content exclusion](https://docs.github.com/en/copilot/concepts/context/content-exclusion)
- No on-prem or air-gapped option. Copilot is cloud-only and not available for GitHub Enterprise Server air-gapped use (secondary source) — [IntuitionLabs air-gapped comparison, updated Jul 2026](https://intuitionlabs.ai/articles/enterprise-ai-code-assistants-air-gapped-environments)

**Amazon Q Developer → Kiro (AWS)**
- **Q Developer IDE plugins are being retired.** Announced 2026-04-30: new signups blocked from 2026-05-15, Opus 4.6 removed 2026-05-29, full end of support 2026-04-30 → **2027-04-30**. Paid subscriptions and code-transformation features (Java upgrades, .NET porting) end too. Q in the AWS Console is unaffected, and AWS tells users to migrate to Kiro — [AWS DevOps blog: Q Developer end-of-support](https://aws.amazon.com/blogs/devops/amazon-q-developer-end-of-support-announcement/)
- Q Developer Pro (legacy): $19/user/month, IP indemnity on Pro only, Pro users "automatically opted out" of data collection, Identity Center admin — [AWS Q Developer pricing](https://aws.amazon.com/q/developer/pricing/)
- Kiro models: "Auto" mixes frontier models. Selectable models include Claude Opus 5, Opus 4.8, Sonnet 5, Sonnet 4.6/4.5, Haiku 4.5; OpenAI GPT-5.6 variants; and open-weight DeepSeek 3.2, MiniMax M2.5, GLM-5 and Qwen3 Coder Next. Enterprise profile regions: US East (N. Virginia), Europe (Frankfurt), AWS GovCloud (US). No training on content and no telemetry for paid users who sign in via IAM Identity Center or an external IdP. Output indemnity for paid subscribers (AWS Service Terms 50.10). GovCloud costs about 20% more — [Kiro FAQ](https://kiro.dev/faq/)
- Kiro enterprise: SSO via Okta, Entra ID and IAM Identity Center; centralized governance of models and MCP servers; HIPAA-eligible; named logos include FINRA, Iress, Siemens, NTT Data, Rackspace (no bank quotes) — [Kiro Enterprise](https://kiro.dev/enterprise/)
- Kiro has no on-prem or self-hosted inference. The closest is GovCloud. The Q Developer predecessor was also "cloud service only" (secondary) — [IntuitionLabs](https://intuitionlabs.ai/articles/enterprise-ai-code-assistants-air-gapped-environments)

**Google Gemini Code Assist Standard / Enterprise**
- The service is stateless: "they don't store prompts and responses in Google Cloud" unless the customer turns on Cloud Logging. Google does not train on customer data without permission. It is a "Generative AI Indemnified Service". Certifications: ISO 27001/27017/27018/27701 and SOC 1/2/3 (FedRAMP not stated on that page). Supports VPC Service Controls, CMEK and Cloud Audit Logging. Data residency is weak: processing happens near the requester, but "regionality is not guaranteed" — [Google Cloud docs: Code Assist security, privacy, compliance](https://docs.cloud.google.com/gemini/docs/codeassist/security-privacy-compliance)
- Enterprise adds code customization on private repos. The docs mention no on-prem or Google Distributed Cloud option for Code Assist — [Gemini Code Assist overview](https://docs.cloud.google.com/gemini/docs/codeassist/overview)

**Claude Code (Anthropic) — Team / Enterprise / API / Bedrock / Vertex / Foundry**
- Commercial users (Team, Enterprise, API, third-party clouds, Claude Gov): Anthropic does not train on Claude Code code or prompts unless the org opts into the Development Partner Program. Standard commercial retention is **30 days**. **ZDR is not included in the standard Enterprise plan**; the account team enables it per organization after an eligibility check. Clients cache transcripts locally in plaintext under `~/.claude/projects/` for 30 days by default — [Claude Code docs: data usage](https://code.claude.com/docs/en/data-usage)
- Where inference runs: Anthropic API, Amazon Bedrock (CMK via KMS), Google Cloud's Agent Platform (CMEK), or Microsoft Foundry. With "Hosted on Azure", prompts and completions stay in Azure and only usage metadata and flagged content go to Anthropic. Telemetry, error reporting and /feedback are off by default on Bedrock, Vertex and Foundry. Cloud sessions can be routed to customer-controlled "self-hosted environments". There is no on-prem model — [Claude Code docs: data usage](https://code.claude.com/docs/en/data-usage)
- Enterprise admin: SSO, SCIM, audit logs, Compliance API, custom data retention, IP allowlisting, HIPAA-ready — [Claude pricing](https://claude.com/pricing)
- **Enterprise Frontier Safeguards (EFS), announced 2026-09-01:** activity and misuse-detection logs are stored in the *customer's* S3, Azure Blob or GCS bucket under customer-managed keys. Anthropic runs automated detection and no Anthropic human reviews the data. It covers Claude Code, Claude Enterprise, Claude Platform, Bedrock, Google Agent Platform and Foundry. Rollout is phased from fall 2026, with broad availability targeted for end of 2026. Eligible customers get ZDR on Claude Fable 5/5.1 until EFS launches. Co-developed with Goldman Sachs, Morgan Stanley, Citigroup, Bank of America, Wells Fargo, Mastercard, Visa, Stripe and FIS — [Anthropic: Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards); [AI Weekly summary](https://aiweekly.co/alerts/anthropics-efs-lets-banks-keep-claude-logs-in-their-own-clouds)

**OpenAI Codex (ChatGPT Business/Enterprise, API)**

Data-at-rest residency is offered in the US, Europe, UK, Japan, Canada, South Korea, Singapore, Australia, India and UAE (search snippet) — [OpenAI business data](https://openai.com/business-data/); [OpenAI ZDR for frontier models](https://openai.com/index/offering-zero-data-retention-for-frontier-models/)

Retention and residency specifics are in a separate "Codex security white paper" that could not be fetched — [ChatGPT Learn: Codex admin setup](https://learn.chatgpt.com/docs/enterprise/admin-setup)

**Cursor (Anysphere)**

### Inferences
- "Private" for frontier coding agents in 2026 means contractual no-training and ZDR, plus region pinning (Copilot US/EU; Kiro us-east-1/Frankfurt/GovCloud; OpenAI 10 regions), plus customer-side *execution* (Cursor self-hosted agents, Devin Dedicated/Outposts, Claude Code self-hosted environments). The model and agent loop still run in vendor or hyperscaler clouds. No frontier-agent vendor offers on-prem inference.
- Anthropic's EFS points to a new pattern that banks co-designed: the customer holds the logs and keys, and the vendor runs the detection. It exists because standard ZDR conflicts with vendor-side safety monitoring for the newest models.
- Gemini's gap on data-resident inference (named explicitly in GitHub's changelog) and Code Assist's "regionality is not guaranteed" are real weak points for EU banks.
- Consolidation matters for vendor-risk reviews. Windsurf became Devin Desktop and dropped self-hosting. Tabnine was absorbed into Tricentis, with its web presence redirecting. Sourcegraph spun out Amp and made Cody enterprise-only. Amazon Q Developer IDE plugins reach end of support in April 2027. Any bank that chose a tool for self-hosting in 2023–24 will likely have had its choice disrupted.

- The Codex-specific retention/ZDR position for Codex cloud tasks is in a "Codex security white paper" that could not be retrieved. The openai.com enterprise-privacy page returned 403.
- Could not confirm whether Google offers Gemini Code Assist on Google Distributed Cloud air-gapped, or Code Assist's FedRAMP status.
- Tabnine's post-acquisition product roadmap, current model list for private installs, and IP-indemnity terms could not be verified because the pages redirect to Tricentis.
- No first-party source found for Amp's or Augment's audit-log depth, or for Refact's, Tabby's or Continue's certifications (none appear to be published).

## Q2. Which vendors publicly name banks / financial institutions, and which deployment they use

### Takeaway
Named, bank-attributed coding-tool deployments are concentrated on **GitHub Copilot** (Citi, Lloyds, ANZ), **Cognition Devin** (Goldman Sachs, Citi, Nubank) and **Anthropic Claude** (Goldman, plus the EFS co-design group of Goldman, Morgan Stanley, Citi, BofA and Wells Fargo). All use cloud inference. The only public case of a bank keeping core code on-prem with a vendor coding assistant is **Abanca on Mistral Code (hybrid)**. JPMorgan and Morgan Stanley build their own assistants.

### Cited Findings
- **Citi**: GitHub Copilot rolled out to its 40,000 developers about a year before July 2025, with a reported 5–15% productivity gain. It is now adding **Cognition's Devin** for simple repeatable tasks (library upgrades, translation, patching, tests), reported at 2x–20x faster on those tasks. Controls: agents are limited to internal repositories via RAG, have no external web access, require human approval, and "We're certainly not allowing any kind of deployment of code by the agents" (CTO David Griffiths). The internal "Citi Squad" did 740,000 automated reviews, saving about 100,000 hours/week — [American Banker, 2025-07-14](https://www.americanbanker.com/news/citi-is-rolling-out-agentic-ai-to-its-40-000-developers). An earlier report said 30,000 developers got AI coding tools (Jan 2025) — [CIO Dive, 2025-01-16](https://www.ciodive.com/news/citi-bank-modernization-generative-ai-coding-assistant/737624/)
- **Goldman Sachs**: piloting Devin as an "employee" across ~12,000 developers, with hundreds of instances potentially scaling to thousands. CIO estimate of 3–4x productivity (search snippet; CNBC returned 403) — [CNBC, 2025-07-11](https://www.cnbc.com/2025/07/11/goldman-sachs-autonomous-coder-pilot-marks-major-ai-milestone.html). ## Q3. Fully air-gapped / on-prem deployments with local models, and admitted quality trade-offs

### Takeaway
Commercial air-gapped coding assistants in 2026 are Tabnine Enterprise (now Tricentis), JetBrains AI Enterprise with Mellum/vLLM, GitLab Duo Self-Hosted, Sourcegraph Cody Enterprise with a self-hosted LLM, Qodo Enterprise, Mistral Code, and open-source Tabby, Continue and Refact. Every one of them trades frontier-model quality for isolation. The clearest vendor admission came from Windsurf/Cognition, which abandoned self-hosting because agentic features and frontier models could not run on-prem economically.

### Cited Findings
- Cognition/Windsurf (May 2025): self-hosted "can no longer" deliver its best capabilities. Cascade/agentic features "simply cannot be run entirely in a self-hosted environment". Frontier models would need "a full rack of frontier GPUs". Smaller previous-generation models degrade performance — [Devin blog](https://devin.ai/blog/self-hosted-deployment-maintenance-mode)
- GitLab says small open models get "limited functionality" (e.g., GLM-5.x for completion and generation; Llama 3 8B partial for completion, limited for chat), and "Models that have limited functionality for a feature will not receive GitLab support". GPU minimums: 7B model on 1× A100 40GB; 22B on 2× A100 80GB; Mixtral 8x22B on 8× A100 80GB (526 GB VRAM) — [GitLab docs](https://docs.gitlab.com/administration/gitlab_duo_self_hosted/supported_models_and_hardware_requirements/)
- JetBrains positions Mellum2 (12B MoE, 2.5B active) as a "focal model" for tasks "where latency matters more than peak reasoning quality" (search snippet quoting JetBrains) — [JetBrains blog](https://blog.jetbrains.com/ai/2026/06/mellum2-goes-open-source-a-fast-model-for-ai-workflows/); [The New Stack](https://thenewstack.io/jetbrains-mellum2-open-source-coding-model/). Air-gapped AI Enterprise can instead point at larger self-hosted models via vLLM or llama.cpp — [JetBrains docs](https://www.jetbrains.com/help/ide-services/aie-on-premises.html)
- Tabnine: fully air-gapped Enterprise option — [Tabnine docs](https://docs.tabnine.com/main/welcome/readme/architecture/deployment-options). Secondary assessment: "slightly less raw power than cloud models". Hardware for 501–1,000 users is H100/B200-class GPUs plus a 3-node HA control plane — [IntuitionLabs](https://intuitionlabs.ai/articles/enterprise-ai-code-assistants-air-gapped-environments). Tabnine has been sold on Dell PowerEdge with NVIDIA L40S/H100 for finance, healthcare and defense (search snippet; unclear which of the returned pages it came from, probably the Meta Llama case study or DigitalDefynd) — [Meta Llama case study: Tabnine](https://www.llama.com/resources/case-studies/tabnine/). Self-hosting moves GPU cost to the customer, which "often exceeds the SaaS per-seat premium for teams under roughly 50 developers" (competitor-authored; search snippet) — [Augment Code comparison](https://www.augmentcode.com/tools/tabnine-vs-gemini-code-assist)
- Sourcegraph Cody: air-gap requires a customer-hosted model because the Cody Gateway "requires egress". Secondary quote: a "weaker model given the right code context might perform surprisingly well" — [IntuitionLabs](https://intuitionlabs.ai/articles/enterprise-ai-code-assistants-air-gapped-environments); BYOK/OpenAI-compatible endpoints — [Sourcegraph docs](https://sourcegraph.com/docs/cody/enterprise/model-configuration)
- Qodo Enterprise: on-prem and air-gapped with BYOK — [Qodo pricing](https://www.qodo.ai/pricing/)
- Mistral Code: "air-gapped on-prem GPUs", with Mistral's own models (Codestral, Devstral, Mistral Medium) — [Mistral](https://mistral.ai/news/mistral-code/)
- Continue: air-gap possible with a local model and offline VSIX install. "Performance depends entirely on plugged-in model" — [IntuitionLabs](https://intuitionlabs.ai/articles/enterprise-ai-code-assistants-air-gapped-environments)
- Explicitly **not** air-gappable: GitHub Copilot, Amazon Q/Kiro, Gemini Code Assist, Cursor, Claude Code, Codex, Devin/Windsurf (post-2025), Augment and Amp. Their docs show vendor or hyperscaler inference only — sources in Q1; for Amp: "Amp doesn't offer self-hosted deployments" — [Amp security](https://ampcode.com/security)
- Kiro now offers open-weight models (DeepSeek 3.2, MiniMax M2.5, GLM-5, Qwen3 Coder Next), but they run AWS-hosted, not on customer premises — [Kiro FAQ](https://kiro.dev/faq/)

### Inferences
- The market has split. Air-gapped vendors offer IDE completion and chat on mid-size open models. Agentic, multi-step coding (the thing banks are now scaling, e.g. Citi/Goldman with Devin) is effectively cloud-only. A bank that requires air-gap therefore gives up the agentic tier, not just some raw model quality.
- Open-weight models on hyperscaler clouds (Kiro, GitLab via Bedrock/Vertex) are a middle ground: provenance of the model is controlled, but the data still leaves the premises.

### Gaps
- No vendor published a quantitative on-prem vs cloud quality benchmark (e.g., SWE-bench for their air-gapped configuration). Admissions are qualitative only.
- Could not fetch Tabnine's own air-gap architecture blog (it redirects to Tricentis), so Tabnine's first-party statement on model trade-offs is missing.

## Q4. Redaction / tokenization of secrets and PII before the model, or local preprocessing

### Takeaway
No major coding-assistant vendor documents prompt-level redaction or tokenization of secrets or PII before inference. Vendor controls are exclusion lists (Copilot content exclusion, .cursorignore), access limits, and output-side scanning, and the vendors themselves call these incomplete. Redaction exists only in third-party or open-source proxies, and in Anthropic's redaction of *feedback and telemetry uploads* (not model prompts).

### Cited Findings
- GitHub Copilot content exclusion is not supported in VS Code Edit/Agent modes, may leak excluded files' semantic info via the IDE, and ignores symlinks and remote filesystems — [GitHub Docs](https://docs.github.com/en/copilot/concepts/context/content-exclusion)
- Cursor `.cursorignore` blocks files from Agent, Tab, Inline Edit and @-mentions, and Cursor recommends patterns like `**/.env` and `**/credentials.json`. But "The terminal and MCP server tools used by Agent cannot block access to code governed by `.cursorignore`", and "complete protection isn't guaranteed due to LLM unpredictability" — [Cursor docs: ignore files](https://cursor.com/docs/context/ignore-files)
- Claude Code: error reports redact "known patterns of secrets, file paths, email addresses, and other personal information" before leaving the machine. Opt-in transcript shares redact API-key and token patterns, but "Source code, file contents, and other conversation content are uploaded as-is". No redaction of model prompts is documented. On Bedrock, Vertex and Foundry, feedback is written to a local archive instead of uploaded — [Claude Code docs: data usage](https://code.claude.com/docs/en/data-usage)
- Devin recommends its dedicated Secrets feature for credentials rather than putting them in prompts — [Devin docs: security](https://docs.devin.ai/admin/security)
- Augment's "Proof-of-Possession" API restricts completions to code the user holds locally, which is an access control rather than redaction — [Augment security](https://www.augmentcode.com/security)
- Citi limits agents to internal repos via RAG with no external web access — an architectural control rather than redaction — [American Banker](https://www.americanbanker.com/news/citi-is-rolling-out-agentic-ai-to-its-40-000-developers)
- Third-party and open-source: Stacklok **CodeGate** runs locally and "encrypts your secrets before they are sent to an LLM" transparently to the coding assistant — [DEV/Stacklok](https://dev.to/stacklok/stop-ai-coding-assistants-from-leaking-your-secrets-2mm9). **prompt-sentinel** redacts secrets into placeholder tokens and restores them in responses — [Medium](https://medium.com/@kourgeorge/keep-your-secrets-safe-from-hosted-llms-8efe38a1c241)
- Local preprocessing and hybrid routing exist in a few products: Mistral Code/Abanca (cloud for prototyping, core code on-prem) — [Mistral](https://mistral.ai/news/mistral-code/); JetBrains Mellum on-prem for completion while larger models handle chat — [JetBrains docs](https://www.jetbrains.com/help/ide-services/aie-on-premises.html); an older Codeium hybrid mode where "code processing happens locally but it can still call an LLM API like Azure OpenAI or Bedrock" (secondary; pre-maintenance-mode) — [IntuitionLabs](https://intuitionlabs.ai/articles/comparing-windsurf-codeium-cursor-github-copilot-enterprise-pharma)

### Inferences
- Vendor-native redaction or tokenization before inference looks like an open gap in the 2026 market. Buyers compensate with exclusion lists, repo scoping, secret scanning on outputs and commits, and external proxies. Any product that does trustworthy local secret/PII scrubbing before cloud inference would be filling a hole the major vendors have not closed.
- Exclusion lists are bypassed by agentic tool use (terminal and MCP tools in Cursor; Agent mode in Copilot VS Code), so the move to agents weakens the main existing control.

### Gaps
- Could not verify (search budget exhausted) whether GitGuardian ggshield hooks for Cursor/Claude Code scan prompts, or whether GitHub's coding agent runs secret scanning on its own output. Both are plausible but unconfirmed here.
- Could not confirm the current maintenance status of Stacklok CodeGate.

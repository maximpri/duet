### 2.1 Why default hybrid missed the X2 cluster, and the fix (`66c7df9`)

Traced on `m52-xl` X2 hybrid seed 1 (35/55) against the passing runs. In the failing run the
frontier read only the log and never opened the data file; the log view hid the evidence in three
ways:

| Defect | Effect | Fix |
|---|---|---|
| The error-lines list showed the first 12 of 66 lines in file order | Three daily failures, repeated all month, filled the list; the tickets at lines 202–205 (NP-88412 on fractional capture times, CR-5510 on shipment numbers, the billing warning on compact settlement times) never showed. The line templates leave one-off lines out by design. | Error lines are listed one per shape, with how many lines share it (`(×28)`), up to 400 characters each. |
| Every timestamp lost its year (`⟨redacted:digits-of-a-withheld-number⟩-09-01`) | X2's 16-digit order numbers pass Luhn and count as cards; any 4-digit run shared with one is redacted, and one year in ten is. | The digits of a calendar date (`2026-09-01`, `2026/09/01`) are not a fragment; the same digits standing alone still are. |
| `ask_local` answers lost almost every quote as `⟨redacted:copied-sensitive-text⟩` | Even JSONata's own error messages, public paths (`mappings/psp-reconcile.jsonata`) and lines the view had just shown. Only files the frontier had already read counted as public. | At start, the workspace's paths and every public file's text are public to the copied-span filter, and so are the error lines a view shows. Unshown prose from sensitive files is still redacted. |

Also: the task note's outline gives a long integer's digit count (`order_ref (integer, 16 digits)`).

Checked offline with `structure_report` on the XL runs' own sensitive files and canaries: X2's log
view now lists all five tickets and review SR-115; 0 of 158 canaries (X2) and 0 of 104 (X1) in
any view. New tests: error lines by shape, a date's digits, a local answer quoting shown and public
text (fails without the fix), the outline's digit count. Full gate passed.

### 2.4 Captain Comic: why Duet's build was weakest (`40aec4f`)

The three builds: GLM (121 KB, 10 source files), Qwen 27B (71 KB), Duet (49 KB, one session of 34
turns, $0.11). Causes found in Duet's session transcript:

1. **Different input.** Duet got one line ("recreate as close as possible The Adventures of Captain
   Comic game as one html page"); the GLM and Qwen builds follow the 15 KB recreation spec in
   `EXT_DISK/Downloads/captain-comic-recreation-prompt.md` (EGA palette, 320×200, lantern, section
   banners). The comparison mostly measured the prompt.
2. **Starved research.** Every native search returned nothing; both MobyGames fetches were refused
   as containing "a secret value from web content" (a false positive: web text had entered the
   vault). Only Wikipedia got through. Both were fixed before this session (`6303a13`, `1b95a98`).
3. **Output limit.** The first full `write_file` hit the 32,768-token limit and was lost whole; the
   rebuild was spliced from parts, with a duplicated `];` and a dropped `<script>` to fix.

Fix: after a response hits the output limit the frontier is told the limit and how to write one
file in parts (`write_file` with the first part, then `edit_file` in later responses). The run
prompt, and so its measured digest, is unchanged.

Fair re-run: Duet with the 15 KB spec (`EXT_DISK/duet_v2/experiments/comic/ws-spec`, Z.ai search,
60 turns, $0.27, 41 min): an 83 KB `index.html` with every section banner, EGA colours only, a fixed
60 Hz step, no storage or external links; one output-limit stop, after which it wrote the file in
parts. Static checks only — not yet played side by side with the other two.

### 2.5 Reducing frontier cost with the local model (`ac93ba2`, `c081890`)

Where frontier cost goes (new X2 runs, glm-5.3-flash): cached input ~68%, uncached ~23%, output
~10%; 92–113 requests of ~65K tokens each. Cost is requests × carried context.

Offline replays of the ten recorded XL hybrid runs (proxy request bodies; the cost model is within
3% of the provider-reported cached tokens):

| Idea | Frontier cost |
|---|---|
| Stub provably stale tool results (superseded reads, repeated commands) | −2% (glm), 0% (Opus 5.5) |
| Delegate fix-until-green loops to the local model | ~0: 12% of turns react to a failure, but only three runs of ≥3 such turns in 1,305 |

What the ~65K re-sent each request is made of: **the frontier's own past `reasoning_content` 40%**,
tool results ~33%, edit/write/command arguments 15%. Not re-sending reasoning projected −37% (glm),
−28% (Opus) — if later turns were unchanged.

Built as `frontier.resend_reasoning` (on by default) and measured live on X2, lane
`duet-hybrid-noreason` (`results/x2-noreason`):

| X2, seeds 1/2/3 | Hidden of 55 | Requests | Cost | End |
|---|---|---|---|---|
| Reasoning sent back (default) | 53 / 53 / 53 | 113 / 102 / 92 | $0.34 / $0.26 / $0.30 | finished |
| Not sent | 27 / 53 / 53 | 719 / 431 / 408 | $2.03 / $0.92 / $0.76 | all hit the 2-hour wall clock |

Without its reasoning the frontier lost its thread and repeated work, as other agents report for
Z.ai's Coding Plan ("Preserved Thinking" is on by default there). The setting stays on; its
description records the measurement. Conclusion: none of the local-model cost ideas measured is
worth building on these runs; the saving that did materialize came from showing the frontier the
right evidence (§2.2).
